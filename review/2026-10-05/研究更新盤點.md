## 二、核對時發現的錯誤（這次最重要的收穫）

### 1. 2026-03 研究文件本身（v1.1）

- **§2 的三個關鍵數字誤引出處**：「200K 窗口的模型在 50K 就顯著退化」「累積 80K–150K tokens 後所有模型退化」「35 分鐘後失敗率翻四倍」，當時標註出自 Chroma，實際都出自 Morph 的廠商部落格（2026-03-13），而且原意被改變。
  - 例如「35 分鐘」原文指的是**人類等效任務時間**，不是 session 長度。
  - 這三個數字當時通過了三輪引用校驗。
- **§2「注意力預算」不是 Chroma 的發現**：它出自 Anthropic〈Effective Context Engineering〉。
- **ETH Zurich 的 AGENTS.md 研究已改版到 v3**（2026-09-29），結論有修訂：LLM 生成與開發者寫的檔案，對解題率都沒有顯著影響，但開發者寫的顯著優於 LLM 生成的。
  - 2026-03 的 HumanLayer 文章引用的是 v1。
  - 文中「138 個 agentfiles」的 138 其實是任務實例數。

### 2. 從 LLM-KnowHow 搬入的來源

- **日期**：16 份裡有 15 份錯。多數是猜成「月初」（例如 2026-03-01），也有差到 7 個月的；有一份寫成 2001 年。
- **作者**：常被寫成機構名，或乾脆寫錯。
- **原文沒有或說反的內容**，舉例：
  - prompt-injection 綜述：「34.7% 組織有防禦」原文沒有；「73%」被套到另一件事上。
  - coding agent 分類研究：「sub-agent 正在成為標準」，原文說的是還沒有主流做法，意思相反。
  - Anthropic 長任務 harness：「Opus 4.5 嚴重 context anxiety」，原文說的是 Sonnet 4.5。
  - 12-Factor Agents：Factor 5、Factor 12 的說明是編出來的。
  - ETH 研究：兩篇不同作者的論文被合寫成一份，還補了原文沒有的「兩篇互補」結論。
- **wiki 頁**：`LLM-Behavioral-Risks.md` 的總覽表把「70% context / 30% 模型記憶」寫成「幻覺填補達 70%」；26 頁內容頁中有 11 頁完全沒有引用來源（另一頁是索引）。

**教訓**：LLM 快速產出的知識頁，日期、作者、數字的錯誤率很高，而且錯得很像真的。兩件事寫進了 `CLAUDE.md`：「讀到原文才寫、數字附原文引句」，以及「轉述鏈越長，越要回到原文」。

## 四、業界觀點（2026-03～09）

| 觀點 | 來源 | 和舊設計的關係 |
|---|---|---|
| harness 的每個元件都寫死了「模型做不到什麼」的假設，模型變強後會過期 | [Scaling Managed Agents](../../sources/2026-04-08_anthropic_scaling-managed-agents.md)、[Seeing like an agent](../../sources/2026-04-10_anthropic_seeing-like-an-agent.md) | **挑戰前提**：舊設計是「讓較弱模型照劇本做」 |
| Claude 5 世代：規則改成判斷，system prompt 刪 80% 沒退步 | [Context engineering for Claude 5](../../sources/2026-07-24_anthropic_context-engineering-claude-5.md) | **挑戰前提**；但原文只針對 Opus 5 / Fable 5 這類模型 |
| 規劃步驟對弱模型是準確度鷹架，對強模型只是省成本 | Fan et al. 2026-09（見 knowledge §11） | 同上，有實證支持 |
| 寫程式只留一條線，其他 agent 只給判斷；不帶前情的 review agent 有效 | [Cognition](../../sources/2026-04-22_cognition_multi-agents-whats-actually-working.md) | **相符**：「subagent 不寫碼」＋獨立 review |
| subagent 的價值是把雜訊擋在主 session 外；**反對每一步都加人工確認**，久了會變成反射性按同意 | [Orchestrator's Tax](../../sources/2026-07-16_martinfowler_orchestrators-tax.md) | **部分衝突**：舊設計每階段都有 STOP gate |
| dynamic workflows：用各自獨立 context 的 subagent 對抗偷懶、偏袒自己、目標漂移；重構時讓 subagent 寫碼 | [Dynamic workflows](../../sources/2026-06-02_anthropic_dynamic-workflows.md) | 獨立 context 相符；subagent 寫碼與舊規則衝突 |
| spec 可以是測試套件、HTML mockup、既有函式，不只 markdown | [Context engineering for Claude 5](../../sources/2026-07-24_anthropic_context-engineering-claude-5.md) | 可補充：P1/P2 的產出形式 |
| 規格驅動開發太重：review 負擔過大；新增「實作後比對規格、只補缺漏任務」 | [Spec Kit 2026-06](../../sources/2026-07-01_github_spec-kit-newsletter-2026-june.md) | 可補充：小任務輕量路線、P3 後比對步驟 |
| agent 在迴圈內走 TDD 沒有品質優勢，token 多 3–8.5 倍；改用 mutation testing 檢查測試品質 | [Böckeler](../../sources/2026-08-10_martinfowler_tdd-inside-the-agent-loop.md) | **相符**：只對驗證邏輯走 TDD |
| 給「改這裡會影響哪些測試」的資訊，比給 TDD 流程指令更能減少 regression | [TDAD](../../sources/2026-03-18_arxiv_tdad-test-driven-agentic-development.md) | 可補充 |
| 高 effort 主要花在驗證與邊界情況；規格越細，不同 effort 的結果越接近 | [Spending your effort](../../sources/2026-09-25_anthropic_spending-your-effort.md) | 相符：規格先行 |
| eval 要貼近實際使用、留不給模型看的題目 | [Eval design](../../sources/2026-09-28_anthropic_eval-design-hillclimbing.md) | 可補充：驗證 skill 的方法 |
